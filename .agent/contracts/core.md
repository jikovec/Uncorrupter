# Core execution contract

Source, package manifests, schemas, configuration and executable tests establish
technical behavior. Live Git/GitHub state establishes operational work state;
accepted governance and decisions establish durable policy. Runtime evidence
establishes only the deployment and observation actually inspected. Historical
reports, quoted prompts and prior agent claims are contextual evidence.

Read relevant instructions, orientation and current source before edits. Establish
the task's end state and inspect only material files, reports and dependencies.
Distinguish the committed base from dirty candidates and other open work.

Preserve unrelated changes and their staging state. Use isolated work where overlap
would risk them. Retain byte conventions in existing files and avoid broad cleanup.
Keep established terminology, architecture and behavior unless the task requires a
change; explain necessary changes. Add or upgrade dependencies only when the scoped
outcome requires them, after checking the declared environment and compatibility.

Complete the assigned objective, proportional verification and its authorized
endpoint. Continue independent work when one lane is blocked. Adjacent findings
remain separately identified follow-up, not an implicit scope expansion.

Do not fabricate observations, identifiers, results or completion. Preserve evidence
provenance and distinguish observed facts, supported conclusions, inference and
unknowns. A source file or successful build alone proves no live acceptance.
